# 笛伴 DiziMate 前端产品优化路线

> 目标：把当前版本持续完善为专业、现代化、低压力、可持续使用的陪伴式竹笛练习 App。
>
> 适用范围：前端信息架构、交互流程、视觉系统、实时音频反馈、教学内容、无障碍、性能和本地数据体验。

## 1. 产品目标

每一位零基础用户都应当能够在第一次打开应用后的 60 秒内完成以下闭环：

1. 明确今天要练什么。
2. 看懂目标音和指法。
3. 听到参考音。
4. 完成麦克风检查并开始吹奏。
5. 理解“偏低、偏高、稳定”的原因。
6. 获得一个积极、具体、可执行的下一步。

产品的核心体验不是展示功能数量，而是让用户反复完成：

`选择目标 → 看懂指法 → 听参考音 → 试吹 → 获得反馈 → 再练一次或进入下一步`

## 2. 当前基线

- 当前页面：今日陪练、指法小抄、实时调音器、长音练习、简谱入门、我的曲谱、练习记录。
- 当前默认设置：E 调竹笛、筒音作 5、A4 = 440 Hz、练习容差 ±35 音分。
- 当前架构：常驻 App Shell、Hash 路由、页面组件生命周期、Store、AudioService、Web Audio 音高检测。
- 当前验证：`npm test` 已通过 52 项，`npm run build` 已通过。
- 当前主要问题：首次练习路径不够聚焦、实时反馈不够可解释、移动端信息密度偏高、文字对比度不足、路由历史和部分可访问性存在缺口、实时图表存在高频重绘风险。

## 3. 优先级定义

### P0：必须优先修复

影响首次成功率、核心练习闭环、数据正确性、无障碍或浏览器基础行为的问题。

### P1：应在核心闭环稳定后完成

提升专业陪练感、教学效果、反馈质量和持续练习意愿的问题。

### P2：体验增强与产品扩展

包括数据趋势、曲目生态、PWA、视觉细节和高级设置。

## 4. 实施阶段总览

| 阶段 | 目标 | 优先级 | 建议产出 |
|---|---|---|---|
| 阶段一 | 修复体验底座 | P0 | 路由、标题、麦克风预检、对比度、焦点、语义 |
| 阶段二 | 重做首次练习闭环 | P0 | 3 分钟首次练习、主 CTA、实时反馈状态 |
| 阶段三 | 提升专业陪练能力 | P1 | 调音器、长音、跟曲演奏、报告 |
| 阶段四 | 完善学习内容和记录 | P1 | 指法、简谱、曲谱、练习进度 |
| 阶段五 | 统一视觉和移动端 | P1/P2 | 设计令牌、响应式、图标、动画 |
| 阶段六 | 性能、无障碍和数据能力 | P1/P2 | 高频绘制优化、测试、导出、PWA |

## 5. 阶段一：修复体验底座

### 5.1 路由和页面生命周期

涉及文件：`src/router.js`、`src/main.js`、`src/shell.js`。

任务：

- 将用户主动导航从 `history.replaceState` 改为 `history.pushState`。
- 保留直接访问 Hash URL 的能力。
- 正确处理浏览器后退和前进。
- 路由切换后将焦点移到新页面标题或 `<main>`。
- 页面切换时保持音频、节拍器和麦克风生命周期一致。
- 每个页面更新 `document.title`。
- 为页面添加稳定的 `aria-labelledby`。

验收标准：

- 点击“指法小抄 → 调音器 → 长音练习”后，浏览器后退可以逐页返回。
- 页面切换后屏幕阅读器能立即读出新页面标题。
- 页面切换不会继续播放旧页面的音频或节拍器。
- 浏览器标题与当前页面一致。

### 5.2 麦克风预检

涉及文件：`src/audio.js`、`src/audio-service.js`、`src/views/practice.js`、`src/views/tuner.js`、`src/views/long-tone.js`。

任务：

- 请求权限前展示用途、隐私和设备距离说明。
- 增加“测试麦克风”状态。
- 展示输入音量电平和环境噪声提示。
- 区分等待授权、已拒绝、无设备、设备占用、连接中断和已准备状态。
- 增加“重新检查权限”入口。
- 保留高精度音高模式，同时提供兼容模式。

验收标准：

- 用户在点击系统授权前，已经知道麦克风用途和数据处理方式。
- 每一种常见失败状态都有明确原因和下一步动作。
- 没有麦克风时不会出现模糊的“等待开启”。

## 6. 阶段二：重做首次练习闭环

### 6.1 设计 3 分钟首次练习

涉及文件：`src/views/practice.js`、`src/components/shared.js`、`src/store.js`。

流程建议：

1. 欢迎用户并说明今天的目标。
2. 只展示一个目标音，例如中音 2。
3. 给出简短指法图和“听参考音”按钮。
4. 进行麦克风预检。
5. 显示“吹响后自动开始计时”。
6. 显示音准、音量和稳定时间。
7. 稳定后给出“继续保持”或“进入下一音”。
8. 结束时给出一句总结和下一步。

任务：

- 首页只保留一个视觉主 CTA：`开始陪练`。
- 将节拍器、长音、跟曲演奏和入门路线降为次级入口。
- 设置今日目标：3 分钟、5 分钟或自由练习。
- 显示“当前步骤 / 总步骤”。
- 练习中的时长和已吹准音要实时更新，不等到停止麦克风后才刷新。
- 支持“暂停后继续”和“从上次练习继续”。

验收标准：

- 新用户不阅读说明，也能找到第一步。
- 从点击开始到第一次反馈不超过两次关键操作。
- 练习中实时统计不会停留在 0 分钟、0 个音。

### 6.2 实时反馈状态规范

统一使用以下状态模型：

| 状态 | 标题示例 | 说明示例 | 主要动作 |
|---|---|---|---|
| idle | 准备好后，吹一声 | 参考音会先告诉你目标 | 听参考音 |
| no-signal | 还没有检测到稳定音 | 把笛头移近一些，距离约 30–50 厘米 | 调整距离 |
| low-volume | 声音太轻了 | 吹气更集中一些，保持嘴型 | 再试一次 |
| low-pitch | 声音偏低 | 检查音孔是否漏气，稍微集中气流 | 保持练习 |
| high-pitch | 声音偏高 | 放松一点，减缓气流 | 保持练习 |
| near | 很接近了 | 再保持 0.6 秒 | 继续吹 |
| stable | 稳住了 | 中音 2 已连续稳定 1.2 秒 | 下一音 |
| error | 暂时没有听清 | 检查权限、设备和环境 | 重新检查 |

反馈必须同时包含：音高方向、原因猜测、下一步动作。不能只显示频率数字。

### 阶段二实现记录（2026-10-13）

- 今日陪练入口收敛为“开始陪练”主行动；节拍器、长音、跟曲和入门路线保留为次级入口。
- 首页增加 3 分钟、5 分钟和自由练习目标。目标进度、已练时长和当前步骤在练习中实时更新；计时使用页面级轻量时钟，不重绘练习主体。
- 麦克风开启后，吹响声音即进入本轮计时；暂停会保存本轮时长与当前音符位置，再次开启可从上次位置继续。目标设置、累计时长和恢复位置写入本机练习数据。
- 实时陪练统一为 `idle`、`no-signal`、`low-volume`、`low-pitch`、`high-pitch`、`near`、`stable`、`error` 八种状态。每种状态同时呈现方向、原因和下一步，稳定后明确显示连续稳定 1.2 秒并提示进入下一音。
- 阶段二自动检查增加目标入口、步骤进度和反馈状态覆盖；`npm test`（53 项）与 `npm run build` 均通过。

- `src/components/karaoke.js` 的 50ms 定时器和音高谱重绘。
- `src/views/long-tone.js` 的实时 SVG 图表重绘。
- 页面切音时竹笛图重新挂载造成的布局抖动。
- 手机端长时间练习时 CPU、内存和电量消耗。

目标：

- 普通页面交互保持 60 FPS。
- 实时练习页面在中端手机上不出现明显卡顿。
- 离开页面后麦克风、节拍器、定时器和动画全部释放。

### 10.2 本地数据能力

- 增加 LocalStorage 数据版本迁移。
- 增加导出 JSON 和导入 JSON。
- 增加清空练习记录入口。
- 对导入数据做结构校验。
- 保留当前“声音不录制、不上传”的隐私承诺。

- 页面切换中断音频测试。
- 长时间运行性能检查。

## 11. 每个功能完成时的验收模板

开发每个页面或功能时，必须回答以下问题：

1. 用户进入这个页面后，第一步是什么？
2. 页面是否只有一个主要行动？
3. 用户是否知道当前状态？
4. 出错时是否知道原因和下一步？
5. 是否可以用键盘完成核心操作？
6. 移动端 360px 宽度是否仍然可用？
7. 音频、定时器和动画离开页面后是否释放？
8. 数据是否会被正确保存、恢复和清空？
9. 页面是否符合当前设计令牌和文案规范？
10. 是否补充了必要的单元测试或浏览器验收？

## 12. 推荐开发顺序

按以下顺序推进，不建议跳过前面的底座工作直接扩展曲目或装饰：

1. 修复路由历史、页面标题和焦点管理。
2. 完成麦克风预检和明确的错误状态。
3. 建立统一颜色、字号、按钮和间距令牌。
4. 重做首次 3 分钟练习流程。
5. 重做实时陪练反馈状态和稳定计时。
6. 优化调音器目标模式。
7. 优化长音过程反馈和实时图表性能。
8. 优化跟曲演奏入口、过程和报告。
9. 完善指法、简谱、曲谱的学习进度。
10. 重构移动端导航和页面布局。
11. 增加练习趋势、数据导出和数据管理。
12. 完成视觉回归、无障碍和真实设备验收。

## 13. 完成标准

当以下条件全部满足时，才可以认为本轮前端优化完成：

- 新用户可以在 60 秒内开始第一次有效练习。
- 首页只有一个清晰的主要行动。
- 麦克风状态、音高状态和练习进度始终可理解。
- 偏低、偏高、无声音和设备错误都有可执行建议。
- 浏览器后退、前进、键盘操作和移动端触控均正常。
- 正文和辅助文字具备足够对比度。
- 长音和跟曲练习在中端移动设备上保持流畅。
- 练习记录、演奏报告和本地数据管理完整可用。
- `npm test`、`npm run build`、视觉检查和无障碍检查全部通过。
